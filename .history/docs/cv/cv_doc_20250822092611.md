2. 优化消息链路，解决业务瓶颈：
背景：
主要问题：落地页采用 Lynx （字节跨端语言）编写，下发到客户端需要编译成 native 实现，同时分发静态资源，因此在 B 端创建完成之后引入了一个近线编译的过程。而随着业务的扩展，经常有需要对线上已经编译好的落地页产物更新需求，之前是通过对线上数据库全量扫描刷库的方式，这种方式动则需要几个小时-几天。同时我们发现随着线上落地页的增加，编译任务还是在不断增加，一次编译大约需要 10-50s 不等，编译服务消耗了大量的计算资源，同时懒刷新会影响新落地页编译

 - 引入懒刷新编译机制，避免了服务更新时全量刷新数据的低效操作。
 
 - 基于优先级，有效打散和平衡高并发下的编译任务负载。
  
优化编译任务耗时，从 50s -> 20s 以内
打散编译：编译任务服务从之前的灾备 -> 多活（打散，）
利用限流器 + 分布式锁
