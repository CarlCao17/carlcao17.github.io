# 管理博客

## 两个仓库的职责

- `ObsidianRepo`：私人笔记库，日常在 Obsidian 写作。
- `carlcao17.github.io`：公开博客，保存明确选中的文章、图片、站点设置与发布流程。

博客构建不读取私人仓库，也不需要私人仓库访问凭证。笔记由本地工具按明确标记导出，检查通过后再提交。

## 新写一篇博客

在博客项目目录运行 `./scripts/blog.sh new my-article`，然后编辑 `content/posts/my-article/index.md`。默认是草稿。

运行 `./scripts/blog.sh preview`，在浏览器访问终端给出的本地地址。完成排版检查后，将文章头部的 `draft` 改成 `false`。

## 从 Obsidian 选文章

在要公开的笔记开头添加以下 YAML。`publish: true` 必须是布尔值，不要加引号；`slug` 是稳定的网址名称，发布后尽量保持不变。

```yaml
---
publish: true
title: 我的文章标题
slug: my-article
date: 2026-10-09T19:00:00+08:00
tags: [Go]
draft: false
description: 一句话介绍这篇文章
---
```

先安装导出工具的依赖：

```sh
python3 -m pip install -r scripts/requirements.txt
```

先检查，不写入：

```sh
./scripts/blog.sh import /path/to/ObsidianRepo
```

确认名单，再导出：

```sh
./scripts/blog.sh import /path/to/ObsidianRepo --write
./scripts/blog.sh check
```

工具只导出 `publish: true` 的笔记及它直接引用的图片或 PDF。隐藏目录、插件配置和其他笔记不会复制。

双链转换成普通网页链接。文章引用未批准的笔记、引用不存在或重名的附件、引用草稿，或嵌入另一篇笔记时，工具会停止并提示处理。Obsidian 的块引用、复杂插件语法需人工改成普通 Markdown。代码块中的示例不会转换。

`content/posts/obsidian/` 是导出工具管理的目录，不要直接修改里面的正文；回到 Obsidian 修改后重新导出。改为 `publish: false` 再导出，会从当前输出中撤下文章。公开 Git 历史里的旧版本仍然存在。

## 发布

每次提交前预览、运行 `./scripts/blog.sh check`，然后检查 Git 变更中的正文、图片和名单。

推送到工作分支并发起 PR，可先运行自动检查。合并到 `main` 后，GitHub Actions 会构建并部署网站。

首次启用新流程时，在仓库 Settings → Pages，将 Source 切换为 **GitHub Actions**。这个设置不属于本地代码变更，需要在正式上线时单独完成。

`draft: true` 只防止网页展示；放进公开仓库的草稿仍能在仓库里看到。私人草稿应留在私人笔记库。

## 网站信息改在哪里

| 内容 | 文件 |
|---|---|
| 名称、导航、网址 | `hugo.toml` |
| 首页介绍与侧栏 | `layouts/_default/home.html` |
| 关于 | `content/about/index.md` |
| 项目清单 | `content/projects/index.md` |
| 专题 | `content/topics/` |
| 字体、间距、手机布局 | `assets/css/custom.css` |

主题已随仓库保存，来源和版本见 `themes/typo/UPSTREAM.md`。升级主题先在分支测试。文章和原始笔记保持各自的 Git 备份。

## 旧站资料

旧的 `docs/`、`overrides/`、`mkdocs.yml` 和 `requirements.txt` 保留用于查阅，新站不会将它们生成到网站。迁移文章前先确认作者、出处和公开范围，详见 `legacy/README.md`。
